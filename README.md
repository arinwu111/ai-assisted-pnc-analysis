# 用公开数据做一次财险经营分析，并把 AI 的位置写清楚

一份完整的产险经营分析工作流。以平安产险 2023—2025 年的承保利润改善为样例，回答一个问题：**这一轮改善，多少来自自身能力，多少来自外部环境，还能持续多久。**

可以直接拿走的有三样：约束 AI 的规则文件（`CLAUDE.md`）、把每个数字锁到文件页码的取数纪律、以及第三层那个不依赖任何假设的证伪方法。分析结论本身反而是最不重要的部分，换一家公司、换一个行业，方法照样成立。

## 结论长什么样

把最新一个完整年度当切片：

| | 数值 |
|---|---:|
| 平安产险 2024→2025 综合成本率改善 | 1.4973 pct |
| 同期人保财险、太保产险改善均值 | 1.20 pct |
| 其中仅保证保险一个分部的贡献 | 0.6936 pct |
| 剔除保证险后的剩余改善 | 0.8037 pct |

剔掉保证险这一笔阶段性出清，剩下的改善已经低于同业均值 0.3963 个百分点。也就是说，最新一年里可归为公司持续能力的部分，不足以跑赢行业。

三年窗口的结论方向相反（剔除后仍领先同业 0.7783 个百分点），报告把两个窗口同时摆出来，没有只留下好看的那个，并说明为什么以最新一年为准。

## 方法分三层

想知道改善是不是自己的功劳，就得把它拆成三堆：行业共有的、一次性的、剩下的。第三层不做拆解，只做证伪。

**第一层｜同业差分，剥掉行业共有部分。** 人保财险和太保产险是反事实的替身。三家同期间、同准则、同定义比，行业都在改善的时候，单看自己改善说明不了任何事。

**第二层｜分部权重反推加 Shapley 恒等式，剥掉一次性部分。** 保证险保险服务收入权重从 7.019% 掉到 1.303%，把"权重效应"（缩量本身带来的改善）和"盈利率效应"（分部账面转正带来的改善）分开，得到它单独贡献整体改善 0.6936 个百分点。剩下的那部分才叫能力。

**第三层｜上界反证，判持续性。** 若 2026 年要复刻上年 1.4973 个百分点的改善，保证险需再贡献 0.6936 个百分点，折算下来要求该分部承保利润达到 4,445 百万元，而它全年保险服务收入只有 4,416 百万元。赚的比收进来的还多，做不到。换成比率，要求承保利润率 100.67%，2025 年实际是 47.44%。

靠放量也走不通：按 2025 年的承保利润率倒算，收入要做到 9,371 百万元、是当年的 2.12 倍，而这个险种的保费权重正从 7.019% 一路压到 1.303%。两条路都堵住，这个情景不是被预测排除的，是被算术排除的。

第三层的方法学地位和前两层不一样。前两层是分解，会引入口径争议，对方可以说你的权重取法不对、Shapley 拆分不该这么拆；第三层几乎不依赖假设，只用会计上的上界关系把一个未来情景判死。

说"几乎"是因为它有一个前提，报告里写明了：分部保险服务费用非负。前期准备金若大额回冲，账面承保利润率可以突破 100%。但那属于一次性释放，反而支持"不可持续"的结论，构不成反证。

这个手法可以迁移到任何"某项改善还能不能再来一次"的问题上：找到那个贡献项的物理上限——收入规模、产能、客户总数、可释放的准备金余额——再看要求值是否越界。越界即证伪，不需要争论趋势判断。

## 七条纪律

细则在 `CLAUDE.md`，那份文件是这个项目真正的产出。摘要：

1. 只用公开数据，来源白名单以外的先问，不得使用任何内部信息。
2. 每个数字必须带出处，精确到文件名加页码或表号；做不到出处的数字宁可留空。
3. 口径不可比必须显式标注。2023 年起执行 IFRS 17，与 2022 年及以前不可比，跨这条线的时间序列不准连成一条曲线。
4. 推算不得冒充实测，一律写成"推算值｜方法｜输入来源"三段式，在报告里可追。
5. 假设不得由 AI 代选，必须停下来让作者取值。
6. 券商研报只能当线索，数字必须回原始年报核实。
7. 人机分歧、回查出处、AI 提数出错被抓到，这三类必须记进协作日志，一条都不许省。

第七条对应的 `/05-AI协作日志` 在本地维护，未随仓库发布。第五条在阶段 4 有一处例外，见下面的软肋第三条。

`CLAUDE.md` 里描述的目录结构包含 `/00-原始材料` 与 `/05-AI协作日志`，两者都不在仓库里：前者是版权和体积，后者是作者自留。规则文件保持原样发布，没有为了好看改写。

主报告：`04-报告/平安产险经营分析报告_终版.html`，离线可开，12 张图为内嵌 SVG，无外部依赖。正文只出现数值加上标编号，方法与出处收在附录 12.2 与 12.3。

## 重建报告

报告可以一键重建，但这不等于从原始 PDF 出发的完整复现。

```bash
cd 02-脚本 && python3 build_stage4_report_final.py
```

从 PDF 提取好的数据已经固化在 `01-数据/` 和 `build_stage4_report_v2_data.py` 里，所以这一步不需要原件，产出 35 条推算、35 条来源、30 项机械校验，全部 PASS 才算通过。校验记录印在报告附录 12.5，包括分部收入合计等于整体、赔付率加费用率等于综合成本率、四项变动合计等于净利润变动这类恒等式。正文里 35 处推算上标和 210 处来源上标都能点到附录对应行。

真正的取数链——从 PDF 抽数、随机抽 10% 回原文复核——需要原始材料，把文件按 `00-原始材料/原始材料清单.csv` 的文件名放回该目录后运行 `build_stage2_data.py` 与 `verify_stage2_audit.py`。

13 个脚本里有 4 个 `.mjs` 依赖当时的执行环境（`@oai/artifact-tool`），本地跑不起来，留在仓库里是作为过程记录。可运行的主链路是 9 个 Python 脚本那条。

## 这份分析的软肋

写在前面，省得读者自己找。

**同业那把尺子不干净。** 用来剥离行业因素的 1.20 个百分点，没有对人保和太保做同口径的一次性项目剔除。它们各自有没有类似的信保出清或准备金释放，公开披露不足以判断。所以"剔除保证险后跑输同业"是方向提示，不是精确的能力排名。这是最容易被打的一处，欢迎补充数据来推翻。

**能力只能被证伪，不能被度量。** 赔付率拆不出出险频次与案均赔款，分险种综合费用率未披露。公开数据能说明改善的大头不来自能力，但没法正面量出能力有多强。报告没有用任何替代指标顶替这块空白。

**预警阈值是 AI 判断，不是作者定档。** 项目铁律要求假设由作者取值，阶段 4 是唯一例外：指标体系的黄线红线（整体 COR 98%/100%、车险 97%/99%、核心非车 99%/100%、趋势 0.5/1.0 个百分点）与专题触发规则由 AI 提出、作者审阅采用，未逐项独立定档。报告与阈值表都写明这些是管理判断，不是监管线或行业统一标准。换到真实经营场景，这一层应当由业务方定。

**同业均值是两家简单平均。** 人保财险与太保产险等权，未按保险服务收入规模加权，而两家规模差异明显。改用规模加权，基准值与平安超额都会变。全文"同业均值""平安超额"均为简单平均口径，报告第 8.5 节已标注。

**保证险贡献建立在推算口径上。** 该险种 2025 年未进入年报前五大险种表，其分部 COR 由分部报告的收入与承保利润倒算，不是披露值。Shapley 对称分解也只是拆法之一，换基期法或末期法，盈利率效应与权重效应各自的数会变，合计贡献不变。

**保证险的利润构成看不透。** 2025 年披露的未决赔款准备金有利进展没有按险种分拆，无法确认该分部利润里有多少来自准备金释放，所以它的推算 COR 不能当作新增业务的稳态盈利率。

**新能源那一段是敏感性，不是实测。** 燃油车与新能源的 COR 差取 0—5.44 个百分点的区间，上限是在"新能源仍处于承保盈利"约束下反推的条件边界，不是公司披露的实测差距。

看出别的问题，欢迎开 issue 指出具体的表号、页码和数值，比泛泛说"结论不对"有用。
